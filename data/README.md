# 城市发展指标 · 数据脚本

小程序的全部 GDP 数据都由这里的脚本生成，然后写进微信云开发数据库。小程序运行时通过云函数读库，不直接访问统计局。

```
国家统计局接口 ──(fetch)──────────┐
城市统计年鉴快照 ──(import)───────┼─► build（合并 + 计算）─► validate（校验）─► upload ─► 云数据库 ─► 云函数 ─► 小程序
人工录入 CSV ────────────────────┘
```

> **更新数据不需要发布小程序。** 数据和代码是分开的：录完数据、跑完 `upload`，用户下次打开或下拉刷新就能看到，不经过微信审核。只有改页面、改功能才需要发版。

## 环境要求

- Node 22 及以上（用到原生 `fetch`、`Map.groupBy`、`process.loadEnvFile`）
- 能访问 https://data.stats.gov.cn （统计局网站有防火墙，请求过快会被拦，脚本已内置间隔和重试）

## 快速开始

```bash
npm install
npm run all          # 生成地区字典 → 抓统计局 → 合并计算 → 校验
npm run upload:dry   # 预览：每个集合要写入多少条
npm run upload       # 写入云数据库（先完成下一节的配置）
```

## 配置云开发

脚本用腾讯云 API 密钥写库，只需配置一次：

1. 微信开发者工具 → 云开发 → 设置，复制**环境 ID**。
2. 云开发环境需要关联腾讯云账号（云开发控制台里按提示关联）。关联后到 [腾讯云 API 密钥](https://console.cloud.tencent.com/cam/capi) 创建 SecretId / SecretKey。建议用子账号，只授予云开发权限。
3. 复制 `.env.example` 为 `.env` 并填写：

```bash
cp .env.example .env
```

```
TCB_ENV=你的环境ID
TENCENTCLOUD_SECRETID=...
TENCENTCLOUD_SECRETKEY=...
```

`.env` 已在 `.gitignore` 中，不要提交。

**不想配置密钥？** 也可以手动导入：云开发控制台 → 数据库 → 选中集合（没有就先新建，名称见[输出集合](#输出集合与字段)）→ 导入 → 选择 `output/jsonl/` 下同名的 `.jsonl` 文件 → 冲突处理选「Upsert」。

## 人工录入

统计局接口抓不到的地方新数据和修订值录在 `manual/gdp_manual.csv`。可以用 Excel、Numbers 或飞书多维表格编辑，导出时选 **CSV（UTF-8）**，表头保持不变。历史城市全市年度数据另由 `raw/city-yearbook.json` 批量接入，人工录入仍优先于自动来源。

### 更新城市年鉴快照

`raw/city-yearbook.json` 是从 CNKI《中国城市统计年鉴》数据快照筛出的城市全市 GDP 和年鉴公布的 GDP 增长率（实际增速）。来源快照的覆盖为 2015–2016、2018–2023，不包含 2017；缺失记录不插值。获取更新的原始 `data.json` 后运行：

```bash
node scripts/import-city-yearbook.mjs /path/to/data.json
```

构建时国家统计局接口数据优先于年鉴快照，人工 CSV 优先于两者。年鉴中的缺值或口径差异仍需按地方统计部门发布数据复核。

### 字段

| 字段           | 必填           | 说明                                                               | 示例                       |
| -------------- | -------------- | ------------------------------------------------------------------ | -------------------------- |
| `level`        | 是             | `city` 或 `province`                                               | `city`                     |
| `region`       | 是             | 地区名，全称或简称都行                                             | `苏州` / `苏州市` / `甘孜` |
| `province`     | 城市重名时必填 | 所属省，全称或简称                                                 | `江苏`                     |
| `year`         | 是             | 年份                                                               | `2026`                     |
| `period`       | 是             | `Q1` 一季度、`H1` 上半年、`Q3` 前三季度、`FY` 全年，都是**累计值** | `H1`                       |
| `gdp`          | 是             | 地区生产总值，单位亿元                                             | `12854.3`                  |
| `real_growth`  | 否             | 实际增速，填百分数，不带 % 号；没公布就留空，**不要自己算**        | `5.6`                      |
| `source_url`   | 是             | 数据出处链接，没有就不能导入                                       | `https://...`              |
| `published_at` | 否             | 发布日期                                                           | `2026-07-25`               |
| `note`         | 否             | 备注                                                               | `初步核算数`               |

以 `#` 开头的行是说明，会被忽略。

### 规则

- 同一地区、同一年、同一期次只录一行；重复时后面的行覆盖前面的。
- 人工数据**优先于**接口数据。发现统计局接口的数据有误，或者有更新的修订数，直接在这里录一行即可覆盖。
- 实际增速只能填官方公布的值，不能用总量推算，否则会和名义增速混淆。
- 季度要填累计值：「上半年」是 1~6 月合计，不是第二季度单季。

### 去哪找城市数据

1. **先找省级统计局的分市汇总表**，通常在「统计数据 → 主要指标」或季度「全省经济运行情况」里，一次能录完一个省的所有城市。
2. 省里没汇总的，去该市统计局找「x 季度经济运行情况」新闻稿，全年数据也可以看次年发布的统计公报。
3. 首发前至少录完上一年全年（FY）数据，季度数据按发布节奏逐步补。

## 日常更新流程

地方统计局一般在季度结束后 2~6 周内陆续发布数据，国家统计局数据库入库会更晚一些。发布期建议每天跑一次，其他时间每周检查一次。

| 期次     | 大致发布时间                             |
| -------- | ---------------------------------------- |
| 一季度   | 4 月中旬 ~ 5 月                          |
| 上半年   | 7 月中旬 ~ 8 月                          |
| 前三季度 | 10 月中旬 ~ 11 月                        |
| 全年     | 次年 1 月中旬 ~ 2 月（年度终核数据更晚） |

每次更新：

```bash
npm run fetch                            # 1. 抓统计局最新数据
# 2. 把新发布的城市数据录进 manual/gdp_manual.csv
npm run build && npm run validate        # 3. 计算并校验，处理所有 ❌ 错误，确认 ⚠️ 警告
npm run upload                           # 4. 上传，只传有变化的数据
```

上传完成后不需要发布小程序。录入的 CSV 记得提交到 git，方便追溯。


### 更新常住人口榜

人口记录按 `data/manual/city_population.csv` 中的城市代码和年份维护，单位是“人”。一城一年只保留一条；拿到官方统计公报、统计局人口数据或人口普查结果后，追加记录并写上对应的来源链接与来源名称。不要用户籍人口或区辖区人口代替全市常住人口。构建并上传：

```bash
cd data
npm run build:population
npm run upload -- --only=city_population
```

人口榜会对每个城市选年份最新的已收录记录；不同城市统计年份可能不同，旧年份记录会在榜单行内标“待更新”，顶部显示最新年份覆盖数，底部显示各年份和来源。2025 年目前有 32 个重点城市记录：其中已找到单城官方来源的记录直接引用官方统计公报，其余记录来自标注“各市统计局”的公开汇编页，来源名称会明确标注。原先缺失的 30 个城市已补入 2020 年七普人口；这些值按公开汇编页展示精度（0.1 万人）录入，行内标“约”，不伪装为精确到个位的官方数。后续优先用单城官方数据追加更高年份记录；如果来源精度较粗，应在来源名称和展示标记中保留精度说明。

## 计算规则

- **增长量** = 本期总量 − 上年同期总量；**名义增速** = 增长量 ÷ 上年同期总量 × 100%。上年同期使用库里的最新值；统计局修订过的数据，接口返回的就是修订后的值。
- **实际增速** = 统计局公布的指数（上年同期 = 100）− 100，不做任何推算。
- **全年数据**优先用分省年度数据库的数值（终核数），没有时用季度数据库的四季度累计值。
- **排名**按总量降序，总量相同名次并列（1、1、3）。不展示的地区（`hidden`）不参与排名。
- **名次变化** = 上年同期名次 − 本期名次。
- **城市全国排名**只在已有数据的城市之间排。`periods.city_count` 表示本地已收录的城市数，不等同于官方已发布数；页面未有记录时显示「暂无数据」。

## 校验规则

| 级别                | 规则                                                                                                          |
| ------------------- | ------------------------------------------------------------------------------------------------------------- |
| ❌ 错误（阻止上传） | 缺少来源链接；GDP 不是正数；CSV 里的地区找不到、重名未区分、期次或数字格式错误（这几项在 build 阶段就会报错） |
| ⚠️ 警告（人工确认） | 实际增速超出 −10%~15%；总量同比变化超过 30%；省内所有城市都有数据时，城市合计与全省总量偏差超过 3%            |

2020、2021 年受疫情和低基数影响，增速类规则不检查。阈值在 `lib/config.mjs` 的 `CHECK` 中修改。

## 和小程序的配合

- **数据更新不需要发版**，见开头说明。
- **地区字典不要打包进小程序**：小程序启动时从云数据库读取 `regions` 并缓存到本地，按版本号判断是否需要更新。这样行政区划调整（撤市设区、改名）也不用发版。
- **前端缓存**：如果小程序把榜单数据缓存在本地，用 `periods.updated_at` 判断是否过期。
- **运营配置**（广告开关、热门搜索、热门对比、下次发布时间）放在 `app_config` 集合，直接在云开发控制台修改，不归本脚本管理。

## 常见问题

**统计局接口报错或返回空**

先在浏览器打开 https://data.stats.gov.cn 看看能否访问。如果网站正常，可能是改版后指标 ID 变了，重新获取方法：

1. 进入「地区数据 → 分省季度数据 → 国民经济核算 → 地区生产总值」。
2. 打开开发者工具的 Network，找到 `stream/esData` 请求，请求体里的 `cid`、`indicatorIds`、`rootId` 就是 `lib/config.mjs` 里要更新的值。年度、城市数据同理。

旧版接口 `easyquery.htm` 已被统计局封禁（返回 403），网上的老教程不要再用。

**最新一期抓下来是空的**

正常现象。统计局数据库在官方新闻发布后才入库，期间接口返回空值，脚本会跳过。等入库后再跑 `npm run fetch`；急着上线的话，可以先把官方新闻稿里的数据录进 CSV。

**上传中途失败**

直接重新运行 `npm run upload`。已成功的文档记在缓存里，只会重试失败和未上传的部分。

**云数据库里的数据和本地对不上**

用 `npm run upload -- --force` 全部重新写入。比如在控制台手动改过数据、或者换了云开发环境时。

**录错了一条，想删掉**

在 CSV 里删掉这一行只会让本地不再生成这条数据，**脚本只写入不删除**，云数据库里的旧记录还在。需要到云开发控制台手动删除 `gdp_records` 和 `gdp_stats` 中对应 `_id` 的文档，然后重新 `build` 并上传，排名会自动更新。

**一次上传会写多少条**

首次约 4,000 条（四个集合合计）。之后是增量上传，一般每次只有新一期数据加上受影响的排名变化，几百条以内，远低于云开发免费额度。
